# 本项目的目标与验收口径

用户最后确认的目标：选择适合的空投/明确奖励活动，运用 AI 和 Cloudflare 自动完成搜索、风险收益核算、获用户批准后的参与，以及对账复盘。

## 策略优先级

1. 优先研究小本金、以任务及真实产品体验换奖励的活动，包括明确奖励任务与低成本早期交互；不再以 Launchpool 或存款 APR 为主线。
2. 未公布空投分配规则的项目，收益标为未知，积分不按现金入账；不能编造获奖概率。
3. 每项任务单独核查自动化许可、资格、截止时间、人工时间及所有费用；每个具体参与方案必须先批准。单账户真实参与，不规避女巫检测。
4. 社交发布、账户授权及资金操作分别列入批准范围，不因批准研究而自动执行。
5. AI 项目悬赏属于可比较的相邻方向，并非空投；尚未授权注册或提交作品。没有合格机会时等待。

## 必须完成的闭环

官方信息收集 → 资格/风险/收益分析 → 全成本核算 → 具体操作方案和模拟 → 用户批准 → 独立执行限制检查 → 自动参与/查询/领取/退出 → 实际收支对账 → 复盘建议。

每个参与方案在执行前必须获用户明确批准。批准绑定方案版本、账户/链、活动、操作、资金及费用上限、有效期和退出条件；变更必须重新批准。AI 不能批准自己。

成本必须区分：本金占用、交易费用/价差/滑点/Gas/跨链及退出费用、API/搜索/数据/服务器开销、机会成本。未知不能当成零。奖励为零、保守、基准三种情景单独报告；模型臆测不能成为已验证收益。

记账必须区分：已实现收入、本金回收、未实现资产价值、未兑现奖励、确认费用和待核对费用。超时先对账，不盲目重试可能已执行的动作。

复盘只能提出调整，不能自行增加权限、金额或切换新的资金策略。

## 当前交付约束

- 先写程序和测试，交用户检查；未经检查确认不部署、不启用定时任务。
- 未接入模型账户、资金账户和具体合格活动前，不声称已经运行、已经参与或已经赚钱。
- Python 使用 Cloudflare Worker 事件入口和持久绑定；不使用本地常驻循环、进程信号或本地数据库作为云端持久状态。
- 资金参数、密钥不提交公开仓库。签名权限与模型隔离。

## 最终验收

代码测试通过只是其中一项。上线前还要用选定活动完成：真实只读数据检查、模拟、批准阻断/放行测试、最小金额试运行、到账/退出核对、通知送达、暂停和异常恢复。
